### 本机接口鉴权检查

| 检查项 | 结果 |
| --- | --- |
| 数据接口 `GET /threatbook/state` | ✅ 经 DSH `connection.requestRejection` 校验，无凭据返回 `401` |
| 操作接口 `POST /threatbook/action` | ✅ 同上；未授权请求无法写入或清除 Key |
| 打开文件 / 目录 | ✅ `open-report`、`open-folder` 仅接受 `threatbook-reports/` 目录内的文件与目录，其余路径直接拒绝 |
| 跨站请求（CSRF） | ✅ Host / Origin 校验由 DSH 连接层完成，跨源请求被拒绝 |
| 请求体限制 | ✅ 32 KB 上限，且必须为 `application/json` |

**结论**: 本机接口不再对同机任意进程开放。实测无凭据访问 `state` 与 `action` 均返回 `401`，与 DSH 官方插件 `open-in-app` 的保护级别一致。

## 🛡️ 插件自身安全设计（亮点）

| 安全设计 | 实现方式 |
| --- | --- |
| Key 不出本机 | 仅写入本机 `apikey.json`；`/threatbook/state` 只返回掩码（首尾各 4 位），明文仅存在于 Host 进程内存与文件 |
| Key 不进入模型上下文 | 面板与设置页通过本机回环路由与 Host 通信，Key 不经过会话消息 |
| Key 不出现在代码与仓库 | 仓库与安装包内无任何硬编码 Key；CI 的 `check.mjs` 每次提交扫描硬编码密钥特征 |

| 报告路径受控 | `open-report` / `open-folder` 只接受 `threatbook-reports/` 目录内的已存在文件与目录 |
| 本机接口鉴权 | 面板接口经 DSH 连接层校验，无凭据请求返回 `401`；跨源请求被 Host / Origin 检查拒绝 |
| 无遥测 | 不引入任何统计、上报、心跳逻辑 |
| 可验证 | 全部代码开源、零依赖、发布包附 SHA256，可自行比对 |

## 💡 总体建议

1. **当前状态良好**: 插件为“零依赖 + 全源码 + 常量网络目标 + 接口鉴权”的形态，可审面小，不存在下载执行与供应链传递环节。
2. **建议一**: 企业环境部署时，用 `THREATBOOK_EGRESS_URLS` 指向内网 IP 探测服务，减少对公网探测站的依赖（信息性提醒 1）。
3. **建议二**: Key 应遵循最小授权原则，在微步控制台随时可吊销；不再使用时通过设置页「清除」删除本机文件。
4. **建议三**: 如需权威结论，建议送微步 SafeSkill 或第三方实验室复检本报告结论。

**审计总结**: threatbook-intel 由 Host 与 Web 两个 JavaScript 文件构成，零运行时依赖，不含安装脚本。其网络目标为固定常量（微步 API、微步绑定页、5 个公网 IP 探测服务），不含用户可控的任意地址请求；唯一的子进程调用用于打开浏览器或报告目录，参数以数组传递且目标受白名单约束。面板与设置页依赖的两个本机接口经 DSH 连接层校验，无凭据请求返回 `401`，同机其他进程无法读取或修改插件状态。API Key 仅落盘于本机插件数据目录（0600），不上传、不同步、不进入模型上下文。两项信息性提醒均为设计取舍而非缺陷，已给出对应缓解方式。**未发现供应链投毒、凭据外泄或任意代码执行风险。**
