# 变更记录

本文件记录 `threatbook-intel` 插件的版本变化。发版时在顶部新增一节。

## 1.5.0 — 2026-10-25

适配部分账号只开通了部分接口权限的情况。

- **权限矩阵**：每类指标标明「能定性」所依赖的接口 (IP：ip/query + reputation；Domain：domain/query + scene/ioc；Hash：file/report + multiengines；URL：url/report；CVE：vuln)，判定时逐接口合并，任一可用即可定性
- **无法判定与无记录分开**：当某类指标的关键接口全部无权限或失败时，结论写「权限不足，无法判定」，不再输出「无情报记录」，评分也不再用低分暗示安全
- **全失败文案**：所有接口都因无权限失败时，直接说明「该类型接口均无权限」，而不是笼统的查询失败
- **多引擎兜底**：样本接口无权限但多引擎接口可用时，用多引擎共识 (≥5 家报毒) 支撑判定，并在提示里注明来源是多引擎而非微步单点
- **判定来源可见**：提示行新增「判定来源 / 无权限」明细，摘要结论标注来自哪个接口
- **提示词**：加入两条规则——权限缺失时必须写「权限不足，无法判定」；部分缺失但有可用判定时，以可用判定为准并说明把握度折损

## 1.4.2 — 2026-10-25

修复“微步已判恶意却被打成 P3 低危”的问题。

- **根因**：域名的判定分散在 `domain/query` 与 `/scene/ioc` 两个接口，采集时只读了前者；当 `domain/query` 无权限时事实层为空，评分被算成 5/100，模型据此写成“无情报记录”
- **采集**：域名同时合并 `/scene/ioc` 的判定、严重级别、可信度；`tags_classes` 里的标签 (如 银狐、黑产团伙) 一并纳入事实
- **评分**：微步明确判恶意时，评分下限提到 45-55，不再被其他接口缺失拉低；证据等级同步升到 A
- **提示**：新增「微步判定」一行，注明来源、严重级别、可信度与标签，避免模型只看到空字段
- **提示词**：加入硬规则——只要出现 `is_malicious=true` 或严重级别为高，结论不得写「无情报记录」或「低危」，以微步判定为准
- **回归**：用出问题的那份真实报告回放，该域名从 5/100 (P3 低优) 修正为 70/100 (P1 高优)，等级 A

## 1.4.1 — 2026-10-25

修复按钮在鼠标移开后残留黑色焦点框的问题。

- **原因**：按钮的悬停效果原先用 `onFocus` / `onBlur` 模拟，点击后焦点仍留在按钮上，浏览器默认焦点环就一直画着，看起来像一圈黑边
- **修复**：改用注入样式表统一处理 hover 与 focus；鼠标操作不再出现黑边，键盘 Tab 切换时显示品牌色焦点环 (保留可访问性)
- 输入框同步处理：聚焦时用品牌色描边替代浏览器默认黑框
- 顺带移除不再使用的内联按钮样式，样式集中在同一处维护

## 1.4.0 — 2026-10-25

C2 通联地址单独突出，避免埋在证据里。

- **自动提取**：样本被判定为恶意时，从 `file/report` 的网络行为 (domains / hosts / http) 中提取通联地址，标为 Domain / IP / URL 并注明来源；IP 或域名本身被判为远控时，直接把它列为 C2 候选
- **报告新增段落**：Markdown 报告里单独一节「C2 通联 IOC」，逐条列出地址与来源，并提示封禁优先级
- **摘要与提示行**：状态栏摘要、研判提示各增加一行 C2 清单；研判提示明确要求写进结论与封禁清单
- **AI 总结**：C2 必须先于证据段落点名，并在行动建议里给出逐条封禁 / 拦截清单，禁止埋进证据列表
- **工具描述**：发现 C2 时必须在结论中点名并给出封禁清单
- 提取有前提：仅当样本被判恶意或指标本身被判远控时才列 C2，避免把普通 URL 误标为 C2
- **标签统一**：去掉「API Key」后的冒号，与「出口 IP」「最近查询」的写法保持一致

## 1.3.0 — 2026-10-25

重写研判链路：加入评分、攻击链映射与时效判断，提示词与文案全部自行撰写。

思路参考 (只借鉴方法，措辞与实现均为自写)：Threat Detection 的 IOC 时效阈值与 ATT&CK 映射；soc-alert-triage-pipeline 的加权评分与 P0-P3 分级、攻击链阶段划分；样本分析与应急响应的证据分级；emergency-response 的处置分层 (遏制 → 调查 → 加固)。

- **威胁评分**：判定强度 55 + 多引擎检出 25 + 可信度 10 + 时效 10 = 100，映射到 P0 紧急 / P1 高优 / P2 中优 / P3 低优，并注明未计入告警级别与资产价值
- **攻击链与 ATT&CK**：根据判定标签判断所处阶段 (侦察 / 投递 / 利用 / 安装 / 命令与控制 / 目标行动)，并给出可对应的 ATT&CK 编号
- **IOC 时效**：IP / Domain 30 天、URL 14 天、Hash 90 天，超过后明确提示批量扫描命中率低、误报变多
- **噪声与误报**：IDC / CDN 等共享场景提示封禁的连带影响；判为非恶意时给 C 级证据而不是直接放行
- **工具描述**：按“同事读工单”的顺序要求输出，含评分、链条位置、网络 / 主机 / 账号三类动作、误报条件与待人工拍板事项；评分低于 30 必须留“先观察”一档
- **AI 总结提示词**：六段式 (判断结论 / 支撑证据 / 风险画像 / 行动建议 / 误报判断 / 需要人工拍板的事)，明确要求标注推断、说明情报时效
- 界面摘要同步显示威胁评分与优先级

## 1.2.0 — 2026-10-25

研判质量升级：重写内置提示词，查询结论与 AI 总结更有价值。

- **工具输出新增「研判提示」**：自动给出证据等级 (A 多引擎 ≥5 检出 / B 少数检出或有判定 / C 无检出 / D 无记录)、情报更新时间、未返回数据的接口、域名无解析记录等信号，供模型直接引用
- **工具描述改为分析师输出规范**：结论先行并给置信度、3-5 条注明来源的证据、资产角色与影响面、按网络/主机/账号分级的处置建议、一句判断局限；明确禁止把「无记录」说成「安全」
- **AI 总结提示词重写**：固定五段式 (一句话结论 / 关键证据 / 情报解读 / 处置建议 / 判断局限)，要求标注 (推断)、说明时效性、按需补 1-3 个 ATT&CK 技术编号、给出放行条件
- 摘要与报告格式不变，完整字段仍保留在 Markdown 报告中

## 1.1.0 — 2026-10-24

## 1.0.0 — 2026-10-24

首个版本。

- 启动即读取本机网卡 IP 与公网出口 IP，面板可一键复制，便于在微步「我的 KEY」中绑定白名单
- 未配置 Key 时自动打开微步 KEY 绑定页并给出三步引导 (每进程仅自动打开一次)
- API Key 仅写入本机 `<profile>/plugin-data/threatbook-intel/apikey.json`(0600)，不上传、不进入模型上下文
- 自动识别输入类型 (IP / 域名 / MD5·SHA1·SHA256 / URL / CVE-XVE 等) 并执行多接口完整查询：
  - IP：`ip/query` + `scene/ip_reputation` + `ip/adv_query`
  - 域名：`domain/query` + `domain/adv_query` + `domain/sub_domains` + `scene/ioc` + `scene/domain_context`
  - 文件：`file/report`(summary / multiengines / signature / static / network / dropped / pstree / strings)+ `file/report/multiengines`
  - URL：`url/report`，无报告时自动 `url/scan` 并轮询
  - 漏洞：`vuln`(VPR / CVSS / PoC / 修复方案 / 补丁 / 在野利用)
- 每次查询落盘完整原始 JSON 与完整 Markdown 报告到工作区 `threatbook-reports/`
- 提供 `threatbook_lookup`、`threatbook_status` 两个工具；面板支持「AI 总结」「打开报告」「打开目录」
- 设置页提供全部网卡 IP、绑定说明、Key 更换 / 清除 / 连通性测试
